Pins the iOS and Android native SDKs exactly to 4.15.3.
No JavaScript / TypeScript API changes.

- Android: `startVerification` and `startVerificationWithWorkflow` no longer stay pending when the app is sent to the background. A verification started while the app is backgrounded now waits for the app to be resumed before it opens, and a verification whose screen is closed without a result (for example the app reopened from the launcher icon) settles as `cancelled` or fails when the host is destroyed, so the returned promise always settles once.
- Native 4.15.3: the Travel Rule transfer flow asks for the wallet choice before Continue, resumes the company list with the earlier answer after the proof step, and guards against sending twice (the native side of the hosted flow).
